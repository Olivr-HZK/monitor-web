# 休闲游戏监测网站 - 周报

**周期**：本周  
**项目**：休闲游戏监测（监测汇总平台 - 休闲游戏子模块）

---

## 一、本周进度概览

本周主要完成了**休闲游戏检测**子站的闭环：从独立入口、数据展示、排行榜、到周报推送与使用文档均有覆盖，并统一了登录方式与数据源隔离（微信/抖音 vs SensorTower）。

---

## 二、本周实现内容

### 2.1 产品与入口

- **休闲游戏独立入口**：支持通过 `casual.html`（或构建后的 `/casual.html`）单独打开「仅休闲游戏」的页面，不展示其他监测类型，便于专注使用。
- **主站集成**：在主站顶部导航保留「休闲游戏检测」入口，与监测汇总、AI 热点、趋势检测并列，点击后主区域与右侧监测源均切换为休闲游戏视图。
- **首页快捷入口**：休闲游戏首页提供三个卡片——**微信/抖音小游戏**（跳转榜单）、**SensorTower 榜单**（跳转 SensorTower 排行榜）、**竞品监测**（一键切到竞品社媒列表），减少操作路径。

### 2.2 数据与监测源

- **数据块隔离**：右侧「监测源」将休闲游戏数据分为两块——**微信/抖音小游戏** 与 **SensorTower**，列表与周报按所选数据块分别展示，避免混在一起。
- **分类体系**：在选定数据块下支持多级分类：**周报简要**、**商店页变化**（仅 SensorTower）、**新游戏**（可选平台：微信/抖音/iOS/安卓）、**新玩法**、**玩法拆解**、**竞品**（社媒更新 / UA 素材）；竞品社媒支持按**公司**筛选。
- **数据来源**：休闲游戏检测数据来自 `public/休闲游戏检测/`（如 index.json、周报 md、rankings CSV）与 `public/sensortower_top100.db`（榜单与商店页变化），通过 `reportsLoader`、`sensortowerWeeklyReport` 等加载并映射为统一监测项。

### 2.3 排行榜与详情

- **微信/抖音排行榜**：支持从「新游戏」或首页卡片进入，按平台标签（微信小游戏、抖音小游戏等）切换，表格展示排名、游戏名、开发商、分类、排名变化、更新时间等。
- **SensorTower 排行榜**：支持 iOS/Android Top100 及榜单异动（新进榜、排名飙升等），与 SensorTower 周报数据一致。
- **报告详情与商店页详情**：列表卡片可点击进入周报/日报详情（Markdown 渲染）；部分条目（如商店页变化）跳转商店页详情，详情页返回时保留当前筛选条件。

### 2.4 登录与鉴权

- **静态站 + 访问密码**：在仅部署静态资源（如 GitHub Pages）时，可通过 `auth-config.json` 或构建时注入的 `VITE_STATIC_PASSWORD_HASH` 配置「访问密码」，打开页面先验证密码再展示内容。
- **后端登录**：在启用 `server` 时支持用户名+密码登录，JWT 鉴权，数据请求经 `/api/data/` 受保护访问；休闲游戏子站与主站共用同一套 AuthContext。

### 2.5 周报与推送

- **游戏检测周报（SensorTower）**：由 `send_minigame_weekly_reports.py` 从 `sensortower_top100.db` 生成，包含「新进 Top50」「排名飙升 Top10」「商店页更新」三部分，支持飞书互动卡片与企业微信 Markdown 推送。
- **企业微信适配**：企业微信单条 Markdown 有 4096 字节限制，周报按「一+二节」与「三节+底部」拆成两条发送，避免截断；文末附带「查看当周完整周报」链接跳转网站。
- **自动化脚本**：`run_reports.sh`、`run_daily_digest.sh` 支持按 `--content game/hot/ai` 发送；文档中说明每日 10:30 热点+AI 日报、每周一 10:30 游戏检测周报的 cron 配置方式。

### 2.6 文档

- **休闲游戏检测使用说明**：新增 `docs/休闲游戏检测使用说明.md`，涵盖登录方式（静态密码/后端）、各模块内容与使用方式、企业微信端接收周报的说明、周报内容结构、操作速查表及相关文档索引。
- 与现有《登录与后端部署》《自动任务与推送》《监测汇总网站说明》等文档形成互补，便于 onboarding 与日常查阅。

## 三、遇到的问题与应对

| 问题 | 应对与现状 |
|------|------------|
| **企业微信单条 4096 字节限制** | 将 SensorTower 周报按「第三节」拆成两条发送，并在超长时做截断并附「详见平台」链接，保证商店页更新不被截掉。 |
| **静态部署下的「登录」体验** | 采用访问密码 + 前端 SHA-256 哈希比对，不经过服务器；仅做轻量门控，不在文档中承诺防绕过，适合内部分享场景。 |
| **休闲游戏数据来源多（CSV/DB/JSON/md）** | 统一通过 `reportsLoader`、DataContext 等聚合，前端按 `casualGameSource`、`casualGameCategory` 等字段筛选；新增数据需维护 index.json 或 DB 结构，文档中说明了数据目录与脚本依赖。 |
| **独立入口与主站共用路由与鉴权** | 独立入口使用 `casual-main.tsx` + `CasualApp`，路由仅保留休闲游戏相关（首页、排行榜、报告详情、商店详情），鉴权仍用主站 AuthProvider，保证行为一致。 |
| **后端数据路径与静态资源前缀** | 后端 `/api/data/:path` 对路径有白名单（如 `休闲游戏检测/`）；静态模式下依赖 `BASE_URL` 与 `getDataUrl`，部署到子路径时需正确配置 `vite.config` base。 |

## 四、未来方向

1. **数据与更新**  
   - 将微信/抖音榜单与 SensorTower 数据的更新流程固化（定时拉取或同步脚本），减少手工放文件。  
   - 考虑为「新游戏」「新玩法」等自动打标签或关联玩法拆解文档，便于筛选与跳转。

2. **体验与性能**  
   - 列表较多时做虚拟滚动或分页，缩短首屏时间。  
   - 详情页内锚点/目录导航，方便长周报跳转；商店页详情可考虑增加「同开发商」「同分类」等关联入口。

3. **推送与触达**  
   - 企业微信/飞书推送增加「按订阅偏好」筛选（如只推 SensorTower 或只推竞品），或提供摘要长度选项（简版/完整）。  
   - 重要异动（如某款游戏多地区新进 Top10）可做单独提醒或高亮。

4. **运维与可观测**  
   - 定时任务（日报/周报）增加失败告警与重试策略，日志落盘便于排查。  
   - 对 `sensortower_top100.db`、`public/休闲游戏检测/` 等数据新鲜度做简单监控或展示（如「数据更新于 xxx」）。

5. **产品扩展**  
   - 若后续接入更多平台（如其他小游戏渠道），在监测源中增加「平台」维度，与现有微信/抖音、SensorTower 并列。  
   - 搜索与高级筛选在休闲游戏视图下与「监测源」联动，支持按游戏名、公司、时间范围组合查询。
