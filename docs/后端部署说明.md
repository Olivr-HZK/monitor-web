# 后端部署说明

前端托管在 Google Pages / GitHub Pages 时，需要把 Node 后端单独部署到一台「能跑 Node 且能公网访问」的服务上，这样用户在托管页点击「申请玩法解析」时，请求会发到你的后端，你就能收到并写入 `data/gameplay_requests.json`（或通过飞书/企微通知）。

下面用 **Railway** 和 **Render** 两种方式从零教你部署（都有免费额度，适合个人/小团队）。任选其一即可。

---

## 一、用 Railway 部署（推荐，步骤少）

Railway 支持「连 GitHub 仓库一键部署」，部署后得到一个 `https://xxx.up.railway.app` 的地址。

### 1. 准备

- 确保本仓库已推到 **GitHub**（或 GitLab 等 Railway 支持的源）。
- 在项目根目录的 **`.env`** 里准备好要带给后端的变量（见下文「环境变量」）。部署时在 Railway 网页里再填一遍即可，不必把 `.env` 提交到仓库。

### 2. 在 Railway 创建项目并连仓库

1. 打开 [railway.app](https://railway.app)，用 GitHub 登录。
2. 点击 **Start a New Project** → 选 **Deploy from GitHub repo**。
3. 选择你这个仓库（如 `Oliver-HZK/monitor-web` 或你的仓库名），授权后 Railway 会拉取代码。

### 3. 使用 Docker 构建（避免 node: command not found）

仓库里有 **`Dockerfile`** 和 **`railpack.json`**。若部署时出现 **`node: command not found`**，说明当前在用 Railpack 且最终镜像里没有 Node，请改为用 **Docker** 构建：

**做法 A（推荐）**：在 Railway 该服务的 **Settings** 里找 **Build** / **Builder** / **Build Command** 等，若有 **「Dockerfile」** 或 **「Docker」** 选项，选它，然后重新部署。

**做法 B**：暂时不用 Railpack，让 Railway 自动用 Dockerfile：
- 把根目录的 **`railpack.json`** 改名为 **`railpack.json.bak`**（或删除）。
- 提交并推送后重新部署，Railway 会检测到 **`Dockerfile`** 并用其构建，镜像里会包含 Node 20。

### 4. 环境变量

在 Railway 该服务的 **Variables** 里添加（和本地 `.env` 对应）：

| 变量名 | 是否必填 | 说明 |
|--------|----------|------|
| `PORT` | 选填 | Railway 会自动注入，一般不用改。 |
| `JWT_SECRET` | 建议填 | 登录用，生产环境建议随机字符串。 |
| `LOGIN_USERNAME` | 选填 | 默认 `admin`。 |
| `LOGIN_PASSWORD_HASH` | 选填 | 若需登录校验，运行 `node server/hash-password.js 你的密码` 得到哈希后填这里。 |
| `FEISHU_WEBHOOK_URL` | 选填 | 申请玩法解析后发飞书通知。 |
| `WECOM_WEBHOOK_URL_REAL` 或 `WECOM_WEBHOOK_URL` | 选填 | 申请玩法解析后发企微通知。 |
| `CORS_ORIGIN` | 选填 | 不填则允许任意来源 `*`；填则只允许该域名，如 `https://你的静态站域名`。 |

保存后 Railway 会重新部署。

### 5. 拿到后端地址并给前端用

1. 在 Railway 该服务里打开 **Settings → Networking → Public Networking**，生成一个 **Public Domain**，得到类似：  
   `https://监测汇总-production-xxxx.up.railway.app`
2. 复制这个地址（不要末尾斜杠）。  
3. 在**本地**构建前端时指定后端地址并部署到 Google Pages：
   ```bash
   VITE_API_BASE=https://监测汇总-production-xxxx.up.railway.app npm run build
   ```
   再把 `dist` 部署到 Google Pages。这样托管页上的「申请玩法解析」就会发到该地址。

### 6. 查看申请记录

- 若配置了飞书/企微 Webhook，申请会推送到对应群/会话。  
- 若要看文件：Railway 当前**不直接提供容器内文件浏览**，申请会写在容器内的 `data/gameplay_requests.json`，重启/重新部署后可能被清空。若需长期保留，可后续把写入改为数据库（如 Railway 的 PostgreSQL）或外部存储；当前方案适合「主要靠飞书/企微通知收到申请」。

## 二、用 Render 部署

Render 也支持从 GitHub 部署，免费 tier 足够跑这个小后端。

### 1. 创建 Web Service 并连仓库

1. 打开 [render.com](https://render.com)，用 GitHub 登录。  
2. **Dashboard → New + → Web Service**，选你这个仓库。  
3. 配置：
   - **Runtime**：Docker（若选 Docker，会用到仓库根目录的 **Dockerfile**）。
   - 或 Runtime：Node，**Root Directory**：`server`，**Build Command**：`npm install`，**Start Command**：`node server.js`。

### 2. 环境变量

在 **Environment** 里添加与上面 Railway 相同的变量（`PORT` 由 Render 自动注入）。

### 3. 拿到地址

部署完成后，Render 会分配一个 URL，如 `https://监测汇总-xxxx.onrender.com`。  
前端构建时：

```bash
VITE_API_BASE=https://监测汇总-xxxx.onrender.com npm run build
```

再把 `dist` 部署到 Google Pages 即可。

---

## 三、环境变量汇总（复制用）

部署时在平台「环境变量」里可填（按需）：

```env
# 登录（生产建议设置）
JWT_SECRET=你的随机密钥
LOGIN_USERNAME=admin
LOGIN_PASSWORD_HASH=  # node server/hash-password.js 你的密码 的输出

# 申请玩法解析通知（可选）
FEISHU_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/xxx
WECOM_WEBHOOK_URL_REAL=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx

# 跨域（可选，不填则允许所有来源）
CORS_ORIGIN=https://你的静态站域名
```

## 四、部署后自测

1. **健康检查**：用 Postman 或 curl 发 POST 测试：
   ```bash
   curl -X POST https://你的后端地址/api/feedback/gameplay-request \
     -H "Content-Type: application/json" \
     -d '{"gameName":"测试游戏","source":"wechat_douyin"}'
   ```
   应返回 `{"ok":true}`。

2. **前端联调**：用 `VITE_API_BASE=https://你的后端地址 npm run build` 打一版，本地 `npm run preview` 或部署到 Google Pages 后，在玩法详情页点「申请玩法解析」，应提示「已收到您的申请」；若配置了 Webhook，飞书/企微会收到一条消息。

---

## 五、常见问题

- **node: command not found**  
  说明当前用 Railpack 构建时最终镜像里没有 Node。请按上文「3. 使用 Docker 构建」改为用 **Dockerfile** 构建，或把 `railpack.json` 改名为 `railpack.json.bak` 后重新部署。

- **部署后 404**  
  若用 Dockerfile，确认根目录有 **Dockerfile** 且内容为拷贝 `server/` 并执行 `node server.js`。若用 Node 直接跑，确认 Start Command 为 `node server.js` 且工作目录在 `server/`。

- **CORS 报错**  
  后端已默认允许 `*`；若设置了 `CORS_ORIGIN`，请填前端实际域名（如 `https://xxx.github.io`），不要带末尾斜杠。

- **申请没收到**  
  先看飞书/企微是否配置正确；若没配 Webhook，申请只会写在服务器上的 `data/gameplay_requests.json`，需用平台提供的日志/文件方式查看，或改为数据库/外部存储。

按上述任选 Railway 或 Render 部署后，用户在 Google Pages 上点击「申请玩法解析」，请求就会到你的后端，你就能获取到。
