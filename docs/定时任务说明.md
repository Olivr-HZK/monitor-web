# 定时任务说明

本文档说明 `monitor-web` 相关定时任务、数据依赖和排障入口。当前监测链已按下面顺序收口：

```text
爬取/入库 -> 镜像到 monitor-web/data/databases -> 检查后端 /api/data -> 推送
```

详细规范见 **[监测链定时任务规范.md](./监测链定时任务规范.md)**，统一调度入口见 **[统一定时调度.md](./统一定时调度.md)**。

## 当前状态

核心监测链代码已经迁入本项目：

| 模块 | 本项目入口 | canonical 数据库 |
|------|------------|------------------|
| 微信/抖音小游戏三榜 | `pipelines/monitor-chain/wechat-douyin/` | `data/databases/wechatdouyin.db` |
| SensorTower 周榜 / US 免费榜 / Arrow Madness | `pipelines/monitor-chain/sensortower/` | `data/databases/sensortower_top100.db`、`data/databases/us_free_appid_weekly.db` |
| 竞品社媒每日爬取 / 周报 | `pipelines/monitor-chain/competitor-social/` | `data/databases/competitor_data.db` |

优先使用统一 job runner：

```bash
./scripts/cron/run_job.sh <job-id>
```

本机 `crontab` 如仍出现 `sensortower-` 或 `Olivr-competitor-monitor` 的旧行，当前只作为过渡入口；对应旧 wrapper 已转发到 `monitor-web/scripts/cron/run_job.sh`，再由统一 runner 调用 `monitor-web/pipelines/...`。等稳定运行一轮后，再把系统 crontab 全量替换成 `scripts/cron/monitor-web-unified.cron.fragment.txt`。

## 周一链路

| 时间 | 任务 | job id / 入口 |
|------|------|---------------|
| 7:30 | 竞品每日爬取 | `competitor_daily_scraper` |
| 7:30 | 微信/抖音小游戏三榜 | `wechat_douyin_weekly` |
| 7:30 | SensorTower 周工作流 | `sensortower_weekly`，默认 `SKIP_SENSORTOWER_WEEKLY_PUSH=1` |
| 7:40 | 竞品周报生成 | `competitor_weekly_period` |
| 8:30 | SensorTower US 免费榜日更 | `sensortower_us_free_daily` |
| 8:50 / 9:50 / 10:50 / 11:50 / 13:50 / 15:50 / 17:50 | 微信/抖音完整性补跑，若已完整会自动跳过 | `wechat_douyin_weekly_rerun` |
| 18:10 | 源库校验、后端 `/api/data` 检查、通过后推送 | `monitor_chain_checked_push` |

`wechat_douyin_weekly_rerun` 是幂等检查：目标周六个榜单组合完整时直接退出；不完整时才补跑。节假日或引力引擎延迟更新时，周一白天会持续多轮探测，`monitor_chain_checked_push` 延后到 18:10，检查失败默认不推送，避免旧数据上线。

## 每日链路

| 时间 | 任务 | job id / 入口 |
|------|------|---------------|
| 7:30 | 竞品每日社媒爬取 | `competitor_daily_scraper` |
| 8:00 | Arrow Madness 日更 | `sensortower_arrow_madness_daily` |

热点、AI 日报、gaming、trustmrr 等已纳入统一调度模板，但不是监测链四库的阻断依赖；它们的迁移按产品域单独推进。

## 主要脚本

| 脚本 | 作用 |
|------|------|
| `scripts/cron/run_job.sh` | 统一入口：补齐 PATH、加锁、写 `logs/jobs/<job-id>.log` 和 `.last_status` |
| `scripts/cron/monitor-web-unified.cron.fragment.txt` | 推荐 crontab 模板 |
| `scripts/cron/install_unified_cron.sh` | 预览或安装统一 crontab，可移除已知旧行 |
| `scripts/db/mirror_databases.py` | 用 SQLite backup API 镜像四库到 `data/databases/` |
| `scripts/sync_dbs_and_deploy.sh` | 源库校验 -> 后端检查 -> 推送三条核心周报 |
| `scripts/check_monitor_chain.sh` | 只做检查，不推送 |

## 日志与状态

| 想看什么 | 路径 |
|----------|------|
| 统一 job 日志 | `logs/jobs/<job-id>.log` |
| 统一 job 最近状态 | `logs/jobs/<job-id>.last_status` |
| 集中链路日志 | `logs/sync_dbs_and_deploy_YYYY-MM-DD.log`、`logs/sync_dbs_cron.log` |
| 最近一次链路状态 | `logs/monitor_chain_last_status.md` |
| 推送幂等 marker | `logs/sent/*.sent` |
| watchdog 输出 | `logs/monitor_web_watchdog.out.log`、`logs/monitor_web_watchdog.err.log` |

## 安装或预览 crontab

预览统一 block：

```bash
./scripts/cron/install_unified_cron.sh --print-block
```

预览合并后的完整 crontab：

```bash
./scripts/cron/install_unified_cron.sh
```

安装并移除已知旧入口：

```bash
./scripts/cron/install_unified_cron.sh --apply --replace-known
```

如果 macOS `crontab` 写入卡住，可临时保留旧行；旧 wrapper 会转发到本项目统一 runner，业务执行仍然走新代码，并写入 `logs/jobs/`。后续应在系统 crontab 可写时完成替换。

## 推送规则

默认周一只推送三条核心周报：

- SensorTower 周报
- 竞品社媒周报
- 微信/抖音小游戏周报

默认不推送“我方产品变化 / 指定产品竞品变化”。需要临时补发时，再显式设置对应环境变量或直接运行具体发送脚本。
