# 开发端 vs 生产端：怎么区分

就记两件事：**开发 = 本机**，**生产 = 服务器**。不搞多套分支、多套托管，区分只靠「在哪跑」和「用哪份配置」。

---

## 一、两套环境，两句话

| 环境 | 在哪跑 | 怎么区分 |
|------|--------|----------|
| **开发端** | 你电脑上 | 跑 `npm run dev` + 本机后端，前端读 `.env.development`，后端读 `backend/.env` |
| **生产端** | 一台服务器上 | 跑 Nginx + 后端进程，服务器上**一份** `.env`（或 systemd 的 EnvironmentFile），只给后端用 |

- **开发端**：改代码、调试，只在你本机生效，不动服务器。
- **生产端**：用户访问的地址，部署在服务器上，前后端都在同一台机、同一域名，用一份配置即可。

---

## 二、开发端（本机）

1. **前端**：项目根目录执行 `npm run dev`，会读 **`.env.development`**，里面写：
   ```env
   VITE_API_BASE_URL=http://localhost:3001
   ```
2. **后端**：在 `backend/` 下执行 `uvicorn main:app --reload --host 0.0.0.0 --port 3001`，会读 **`backend/.env`**（以及根目录 `.env`，可选）。

这样就是「开发端」：前端连本机 3001，后端用本机配置，和服务器无关。

---

## 三、生产端（一台服务器）

思路：**前后端都在同一台服务器、同一域名**。用户只访问一个地址，例如 `https://monitor.你的域名.com`。

- Nginx：对 `/` 提供前端静态文件，对 `/api` 反向代理到本机后端（如 `http://127.0.0.1:3001`）。
- 前端构建时**不设** `VITE_API_BASE_URL`（或设为空），这样前端请求 `/api/...` 会发到当前域名，由 Nginx 转给后端。
- 后端在服务器上只读**一份**环境配置（例如 `/opt/monitor/backend/.env` 或 systemd 的 `EnvironmentFile`），里面写生产用的 `JWT_SECRET`、`LOGIN_*`、`OPENAI_*`、`CORS_ORIGIN` 等。

**区分生产/开发**：看进程在哪跑、读哪份文件。本机跑 + 本机 `backend/.env` = 开发；服务器跑 + 服务器上的 `.env` = 生产。不需要靠「分支」或「不同 .env 文件名」来区分，**靠「机器 + 那一份 .env」** 就行。

---

## 四、服务器上怎么部署（最简）

1. **在服务器上**克隆仓库，进入项目目录。
2. **构建前端**（在项目根目录）：
   ```bash
   npm ci
   npm run build
   ```
   不要设 `VITE_API_BASE_URL`，这样打包出来的前端会走相对路径 `/api/...`。
3. **后端**：在服务器上准备一份只给生产用的 env 文件，例如 `/opt/monitor/backend/.env`，内容参考 `backend/.env.example`，填生产用的密码、密钥、`CORS_ORIGIN`（可填 `https://monitor.你的域名.com`）。
4. **启动后端**（可用 systemd 或 supervisor）：
   ```bash
   cd /opt/monitor/backend
   pip install -r requirements.txt
   uvicorn main:app --host 127.0.0.1 --port 3001
   ```
   确保进程会读刚才那份 `.env`（例如在 `backend/` 下启动，dotenv 会自动读同目录 `.env`）。
5. **Nginx**：  
   - `root` 指向前端构建产物目录（例如 `/opt/monitor/dist`）；  
   - `location /api` 反向代理到 `http://127.0.0.1:3001`。

这样，**生产端** = 这台服务器 + 这一份 backend `.env`；**开发端** = 本机 + `.env.development` + `backend/.env`。简单清晰。

### Nginx 配置示例（生产端同机部署）

假设域名 `monitor.你的域名.com`，前端在 `/opt/monitor/dist`，后端跑在本机 3001：

```nginx
server {
    listen 80;
    server_name monitor.你的域名.com;
    root /opt/monitor/dist;
    index index.html;
    location / {
        try_files $uri $uri/ /index.html;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

HTTPS 用 Let's Encrypt 等申请证书后，在 `listen 443 ssl` 并配好 `ssl_certificate` 即可。

---

## 五、小结

- **开发端**：本机，`npm run dev` + 本机后端，用 `.env.development` 和 `backend/.env`。
- **生产端**：服务器上一套，前端 build 不设 API 基地址，后端用服务器上那一份 `.env`；前后端同域，Nginx 反代 `/api`。
- **区分方式**：不靠分支名或一堆 .env 文件名，靠「在哪跑、读哪份配置」：本机 = 开发，服务器上那一份 = 生产。
