# 监测助手 Agent 落地目标

## 总体目标

把监测助手从“网页右侧聊天框”升级为一个可落地、可运营、可追踪的监测 Agent：它应当能理解用户当前页面和自然语言问题，主动选择合适的站内数据源与工具，给出有数据边界的业务结论，并在网页端和飞书端保持一致的能力、权限和审计口径。

## 目标画像

- **可信**：回答必须说明站内数据边界；不知道就说不知道，不把历史数据包装成实时数据。
- **能查**：对榜单、趋势、竞品、UA、我方产品等问题，能主动调用只读数据工具，而不是泛泛聊天。
- **会解释**：先给结论，再给依据；需要图表时主动生成图表或表格。
- **可控**：用户能停止生成、开启新对话、清空上下文、反馈回答质量。
- **可运维**：管理员能看到模型、工具、数据源、新鲜度、飞书入口等健康状态。
- **可扩展**：网页、飞书、订阅推送复用同一个后端 assistant service，避免多套 prompt 和逻辑分叉。
- **安全**：用户不能直连数据库、执行 SQL 或获取密钥；服务端工具只读、限时、限量、有限流。

## 当前已完成

- 已抽象统一后端服务 `backend/assistant_service.py`，网页和飞书都能复用同一个 `run_monitor_assistant`。
- 已支持 OpenRouter 多轮工具调用、SQLite 只读查询、联网搜索、图表 payload 回传。
- 已加入按问题选择数据库 schema 的逻辑，减少每次请求注入全量 schema 的成本。
- 已加入站内数据新鲜度提示，回答“最新/最近/本周”时有数据边界。
- 已强化 SQLite 工具：只读校验、路径校验、查询超时、结果限量、图表数值列过滤。
- 已支持网页端流式回答、停止生成、多会话、本地会话保存、快捷提问、点赞/点踩反馈、图表展示。
- 已支持网页端 Agent 状态栏，展示模型/provider、站内数据工具、数据更新时间、数据源数量和联网能力。
- 已支持网页端回答依据展示，显示本次回答选中的数据源与触发的工具轨迹。
- 已支持网页端清空当前会话、复制回答、复制整段会话、将上一条问题放回输入框重新改问。
- 已支持飞书事件入口、白名单、事件去重、会话存储、群聊 thread 上下文隔离、清空上下文指令。
- 已收紧飞书群聊 mention 判断，只有艾特配置的机器人显示名才会响应。
- 已加入基础 AI 限流和 `/api/ai/health` 健康检查。
- 已加入轻量审计日志 `data/assistant_audit.jsonl`，记录入口、状态、耗时、数据源和工具次数，并在健康检查里暴露近期运行/错误概览。
- 已修正登录默认密码风险，优先使用 `LOGIN_PASSWORD_HASH`。
- 已清理 `backend/main.py` 中遗留的旧 AI prompt/调用函数，后端入口统一走 assistant service。

## 当前正在推进

- 继续提升网页端可观测性：更细的来源引用、报告链接、站外搜索来源。
- 继续提升评测与回归：为常见业务问题和安全边界建立自动测试样例。

## 后续目标

- 将网页端会话同步到服务端，支持跨设备、权限审计和团队级问题复盘。
- 增加回答引用来源：报告链接、榜单页面、数据更新时间、站外搜索链接。
- 将飞书图表 payload 渲染为图片或消息卡片。
- 增加自动评测集：常见问题、越权问题、最新数据问题、图表问题、飞书群聊 mention 问题。
- 增加运营面板：请求量、失败率、平均耗时、工具调用次数、反馈差评样本。
- 把主动订阅、日报/周报推送、异常提醒收敛到同一套 Agent 服务。
