# 项目整合迁移方案

目标顺序固定为：

```text
爬取/入库 -> 镜像数据库到 monitor-web -> 校验后端 /api/data -> 推送
```

## 第一阶段：数据库先收口

已建立本项目内 canonical 数据库目录：

```text
monitor-web/data/databases/
```

四个核心库对应关系：

| 数据库 | 当前上游 | 本项目内目标 |
| --- | --- | --- |
| `sensortower_top100.db` | `pipelines/monitor-chain/sensortower` | `data/databases/sensortower_top100.db` |
| `competitor_data.db` | `pipelines/monitor-chain/competitor-social` | `data/databases/competitor_data.db` |
| `wechatdouyin.db` | `pipelines/monitor-chain/wechat-douyin` | `data/databases/wechatdouyin.db` |
| `us_free_appid_weekly.db` | `pipelines/monitor-chain/sensortower` | `data/databases/us_free_appid_weekly.db` |

镜像脚本：

```bash
python3 scripts/db/mirror_databases.py
```

它使用 SQLite backup API 生成快照，不直接拷贝正在写入的 WAL 库。

## 第二阶段：爬虫源码逐个迁移

优先顺序：

1. `wechat-douyin`：三榜 Playwright 爬取、CSV 入库、失败诊断、补跑脚本已迁入 `pipelines/monitor-chain/wechat-douyin/`。当前仍可复用旧仓库浏览器登录态作为过渡。
2. `sensortower`：周榜工作流、US 免费榜日更、Arrow Madness 日更已迁入 `pipelines/monitor-chain/sensortower/`。
3. `competitor-social`：每日社媒爬虫、周报生成已迁入 `pipelines/monitor-chain/competitor-social/`。
4. 周边项目：AI news、gaming、trustmrr、festivals 等只在确认属于 monitor-web 产品域后再迁。

每迁一个 pipeline 都要满足：

- 入口在 `pipelines/monitor-chain/<pipeline>/`。
- 数据写入 `data/databases/` 或 `data/artifacts/`。
- 日志写入 `logs/jobs/`。
- 不依赖旧仓库工作目录。
- 通过 `scripts/cron/run_job.sh <job-id>` 可运行。

## 第三阶段：删除旧路径依赖

当某个 pipeline 连续稳定运行一周后：

1. crontab 改为 monitor-web 内部入口。
2. 后端配置移除该库的旧路径 fallback。
3. 旧仓库只保留归档，不再作为生产入口。

说明：本机 `crontab` 写入偶发卡住时，旧仓库的 cron wrapper 会临时转发到
`monitor-web/scripts/cron/run_job.sh`，再由统一 runner 调用 `monitor-web/pipelines/...`，
保证实际生产代码和调度日志已经从本项目执行。
