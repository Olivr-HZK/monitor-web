# 预生产环境部署

按下面顺序做：先建分支并推送，再在 Railway 部署预生产后端，最后部署预生产前端。

---

## 一、创建并推送预生产分支（已完成可跳过）

本地已创建 `staging` 分支时，只需推送到远程：

```bash
git push -u origin staging
```

若尚未创建分支：

```bash
git checkout -b staging
git push -u origin staging
```

之后在 `staging` 上开发，确认无误再合并回 `main` 做正式发布。

---

## 二、部署预生产后端（Railway）

### 1. 新建一个 Railway 项目（与生产分开）

1. 打开 [railway.app](https://railway.app)，用 GitHub 登录。
2. **New Project** → **Deploy from GitHub repo**，选择本仓库。
3. 在新建的服务里（二选一）：
   - **推荐**：**Root Directory** 留空（部署整仓），**Start Command** 填：  
     `cd backend && pip install -r requirements.txt && uvicorn main:app --host 0.0.0.0 --port $PORT`  
     这样后端能访问仓库根目录的 `public`（数据文件）。
   - 或 **Root Directory** 填 `backend`，**Start Command** 填：  
     `uvicorn main:app --host 0.0.0.0 --port $PORT`  
     此时需在 Variables 里设置 **`PUBLIC_DIR`** 指向包含 `public` 的路径（例如用 Volume 挂载），否则数据文件可能不可用。

### 2. 环境变量

在 **Variables** 里添加（可与生产用不同值，便于区分）：

| 变量 | 说明 | 预生产建议 |
|------|------|------------|
| `PORT` | 端口 | Railway 自动注入，可不填 |
| `JWT_SECRET` | JWT 密钥 | 填一组长随机串（可与生产不同） |
| `LOGIN_USERNAME` | 登录用户名 | 如 `admin` |
| `LOGIN_PASSWORD_HASH` | 密码哈希 | 运行 `python -c "from passlib.hash import pbkdf2_sha256; print(pbkdf2_sha256.hash('你的预生产密码'))"` 得到后粘贴 |
| `CORS_ORIGIN` | 允许的前端来源 | 预生产前端访问地址的 origin，见下文「三」 |
| `OPENAI_API_KEY` | 大模型 Key | 可用测试 Key 或与生产相同 |
| `OPENAI_BASE_URL` | 大模型接口 | 如 `https://openrouter.ai/api/v1` |
| `OPENAI_MODEL` | 模型名 | 如 `google/gemini-2.5-pro-preview` |
| `PUBLIC_DIR` | 可选 | 若不填，会使用仓库内 `backend` 的上一级 `public`；Railway 部署时通常需要把 `public` 一起包含在仓库里，或通过 Volume 挂载。 |

说明：后端从 `PUBLIC_DIR`（默认仓库根目录下的 `public`）读数据文件。若按上面「推荐」方式部署整仓并 `cd backend` 再启动，无需单独配置 `PUBLIC_DIR`。

### 3. 生成公网地址

在 **Settings → Networking → Public Networking** 里 **Generate Domain**，得到类似：

```
https://监测汇总-staging-xxxx.up.railway.app
```

复制该 URL（**不要末尾斜杠**），下一步会用到。

---

## 三、部署预生产前端

### 1. 把预生产后端地址写进前端

编辑项目根目录的 **`.env.staging`**（若没有则复制 `.env.staging.example`）：

```env
VITE_API_BASE_URL=https://你上一步拿到的预生产后端地址
```

例如：

```env
VITE_API_BASE_URL=https://监测汇总-staging-xxxx.up.railway.app
```

### 2. 配置预生产后端的 CORS

回到 Railway 预生产服务的 **Variables**，确保：

```env
CORS_ORIGIN=https://olivr-hzk.github.io
```

若预生产前端最终放在别的域名（例如 Vercel 预览地址），则改为该域名的 origin（仅协议+域名，无路径、无末尾斜杠）。

### 3. 构建并推送到预生产分支

在项目根目录执行：

```bash
npm run deploy:staging
```

会依次执行：

- 使用 `.env.staging` 做 **staging 模式构建**（前端请求会发到预生产后端）
- 执行 strip 敏感文件
- 将 `dist` 推送到远程分支 **`gh-pages-staging`**

### 4. 如何访问预生产前端

- **方式 A（推荐）**：再建一个 GitHub 仓库（如 `monitor-web-staging`），把本仓库的 **`gh-pages-staging`** 分支定期推过去，在该仓库的 **Settings → Pages** 里把 Source 选为 `gh-pages-staging`（或 main），即可得到 `https://olivr-hzk.github.io/monitor-web-staging/` 这类预生产地址。
- **方式 B**：用 Vercel/Netlify 连接本仓库，选择 **`staging`** 分支，构建命令填 `npm run build:staging`，在平台环境变量里配置 `VITE_API_BASE_URL` 为预生产后端地址，用其提供的预览 URL 访问预生产前端。

完成后，用预生产前端 URL 打开页面，登录（用户名/密码为预生产后端所配），即可在预生产环境验证功能，再合并到 `main` 并做正式部署。
